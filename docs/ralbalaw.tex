\section{Introduction}
In this homework, we explore real-time planning algorithms for 8 connected grid environments.

\section{Problem}
\subsection{Goal}
A target moves one step at a time in an 8-connected grid environment. Its trajectory is known to the robot prior to the start of the planning process. The goal is to catch the target while accumulating as little cost as possible.

\subsection{Environment}
The environment is an 8-connected grid deterministic and fully observable. The robot knows the costs and occupancy of all cells in the environment at all times including the target's trajectory.

The environment can be as large as \(2000 \times 2000\) cells, while the target trajectory can span around 5500 time steps. A full A* search over this space is infeasible because its worst-case complexity is \(O(b^d)\), where \(b\) is the branching factor and \(d\) is the search depth. Here, \(b=9\), since the robot may move to any neighboring cell or remain still, and \(d\) can reach 5500. Therefore, A* may expand up to \(9^{5500}\) nodes in the worst case, which is computationally impractical.

On top of this computational challenge the robot must plan in real-time as the target is moving, so the planner must be able to make decisions quickly and efficiently.

\section{Methodology}
\subsection{Problem Formulation}
The environment is represented as an 8-connected grid graph with valid cells \(V\). A robot state is \(s=(p,t)\), where \(p=(x,y)\in V\) is its position and \(t\) is the current time step. Each action moves the robot to a neighboring cell or keeps it in place, advances time by one step, and has a traversal cost \(c(p,p')\).

The known target trajectory is \(Q=(q_0,q_1,\ldots,q_T)\), where \(q_\tau=(x_\tau,y_\tau)\) is the target position at time \(\tau\) and \(T\) is the final time step. An interception occurs when the robot reaches \(q_\tau\) at the same time \(\tau\). The objective is to find a valid interception path \(\pi=(p_t,\ldots,p_\tau)\) that minimizes

\[
  J(\pi)=\sum_{k=t}^{\tau-1}c(p_k,p_{k+1}),
  \qquad p_\tau=q_\tau.
\]

For convenience, let \(\mathcal{Q}=\{q_\tau\mid 0\leq\tau\leq T\}\) denote the set of all cells visited by the target.

\subsection{Planning Algorithms}
In this problem, the target moves in real time, and the robot must intercept it before the target reaches the end of its trajectory. In principle, a full A* or Dijkstra search could solve the complete 3D planning problem. In practice, however, such a search requires significant computation and might not finish within the available planning time. The size of the environment and the length of the target trajectory make this approach impractical here.

Real-time heuristic search addresses this limitation by interleaving planning and execution. Some real-time algorithms, such as those considered in this work, operate as follows: at each time step, the planner performs a bounded A* search from the robot's current state, selects the next action, and then uses the local search results to improve the heuristic for future searches rather than discarding all of the information.

In this work, we consider the following real-time heuristic search algorithms:

\begin{itemize}
  \item Local Search Space LRTA (LSS-LRTA) \cite{koenig2009lsslrta}\cite{korf1990realtime}.
  \item Real-Time Adaptive A (RTAA) \cite{koenig2006rtaa}.
\end{itemize}

Let \(C\) be the set of closed states by the bounded A* search, let \(O\) be the set of open states in that local search space but not closed. The algorithms differ primarily in their learning step:

\begin{itemize}
  \item \textbf{LSS-LRTA.}
        LSS-LRTA uses a dynamic-programming update over the local search space. In this implementation, a backward Dijkstra search is used. For every expanded state \(s\in C\), the update is
        \[
          h_{\mathrm{new}}(s)
          =
          \min_{u\in O}
          \left\{
          d_C(s,u)+h(u)
          \right\},
        \]
        This update produces more informed heuristic values, but requires a backward shortest-path computation over the local search space.

  \item \textbf{RTAA.}
        RTAA first computes the minimum open \(f\)-value
        \[
          f_{\min}
          =
          \min_{u\in O}
          \left\{
          g(u)+h(u)
          \right\}.
        \]
        It then updates every expanded state using
        \[
          h_{\mathrm{new}}(s)=f_{\min}-g(s),
          \qquad s\in C.
        \]
        This update requires only a linear pass over the expanded states. It is therefore faster than the LSS-LRTA learning step, although its heuristic updates can be less informed.
\end{itemize}

Both algorithms use the same bounded-lookahead planning framework. They differ only
in the local heuristic update applied after the lookahead search. The complete
framework and the two update procedures are presented in
Section~\ref{sec:real-time-search-framework}.

\subsection{Heuristic}
The heuristic combines three components:
\begin{enumerate}
  \item \textbf{Earliest interception:} Estimates the earliest possible interception using Chebyshev distance.
  \item \textbf{Departure feasibility:} Checks whether interception is still possible before the trajectory ends.
  \item \textbf{Spatial cost:} Estimates the minimum cost to the nearest target position while accounting for obstacles and traversal costs.
\end{enumerate}


\subsubsection{Earliest Interception}
The earliest-interception heuristic gives the exact number of time steps needed to reach the target in a relaxed 3D space with no obstacles and a uniform traversal cost of 1. The Chebyshev distance to a target position is

\[
  d_\infty\!\left((x,y),(x_\tau,y_\tau)\right)
  =
  \max\left(|x-x_\tau|,\;|y-y_\tau|\right).
\]

The heuristic is then

\[
  h_{\mathrm{EI}}(s)
  =
  \min_{t \leq \tau \leq T}
  \left\{
  \tau-t
  \;\middle|\;
  \tau-t \geq
  d_\infty\!\left((x,y),(x_\tau,y_\tau)\right)
  \right\}.
\]

If no time step satisfies the condition, the heuristic returns \(\infty\).

Since this is the exact cost-to-go for the relaxed problem, the heuristic is consistent and provides a lower bound on the cost of the original problem.

A direct approach checks each future target position until the interception condition is met, taking \(O(N)\) time in the worst case for \(N\) remaining positions. However, since the target moves by at most one cell per time step, once the condition becomes true, it remains true for all later time steps. Therefore, binary search can find the earliest feasible interception time in \(O(\log N)\).

\subsubsection{Departure Feasibility}
This is a state feasibility check rather than a cost-to-go estimate. It determines whether interception is still possible from a given state.

Let \(d(p,q_\tau)\) be the minimum number of valid moves from \(p\) to \(q_\tau\) while accounting for obstacles. Since each move takes one time step and the robot can wait, interception at time \(\tau\) is possible when
\[
  t\leq \tau-d(p,q_\tau).
\]
The latest feasible departure time from \(p\) is therefore
\[
  L(p)=\max_{0\leq \tau\leq T}
  \left\{\tau-d(p,q_\tau)\right\},
\]
A state is infeasible when \(t>L(p)\).

This objective can be rewritten as a minimization by defining \(D(p)=T-L(p)\):

\[
  D(p)=T-L(p)
  =\min_{0\leq \tau\leq T}
  \left\{(T-\tau)+d(p,q_\tau)\right\}.
\]

This can be computed using a backward multi-source Dijkstra search over the 2D grid. Each target position \(q_\tau\) is initialized with \(T-\tau\), and each reverse move costs 1. Using the Dijkstra cost \(g\), \(D(p)\) is evaluated during the search as

\[
  D(p)=
  \begin{cases}
    g(p),   & p\in\mathrm{CLOSED},                                 \\
    \displaystyle\min_{u\in\mathrm{OPEN}}g(u),
            & p\notin\mathrm{CLOSED},\;\mathrm{OPEN}\neq\emptyset, \\
    \infty, & p\notin\mathrm{CLOSED},\;\mathrm{OPEN}=\emptyset.
  \end{cases}
\]

The feasibility value is then
\[
  h_{\mathrm{DF}}(s)=
  \begin{cases}
    \infty, & D(p)>T-t,         \\
    0,      & \text{otherwise}.
  \end{cases}
\]

\subsubsection{Spatial Cost}
The spatial-cost heuristic gives the exact cost of reaching the lowest-cost target cell while accounting for obstacles and traversal costs in the relaxed 2D space \((x,y)\). For position \(p\), the heuristic is

\[
  h_{\mathrm{SC}}(p)
  =
  \min_{\substack{\pi=(p_0,\ldots,p_k)\\p_0=p,\;p_k\in\mathcal{Q}}}
  \sum_{i=0}^{k-1} c(p_i,p_{i+1}).
\]

Since the time dimension is ignored, this value is a consistent lower bound on the actual cost in the full 3D space. It is computed using a backward multi-source Dijkstra search initialized with every cell in \(\mathcal{Q}\). Using the Dijkstra cost \(g\), the heuristic is then defined as

\[
  h_{\mathrm{SC}}(p)=
  \begin{cases}
    g(p),   & p\in\mathrm{CLOSED},                                 \\
    \displaystyle\min_{u\in\mathrm{OPEN}}g(u),
            & p\notin\mathrm{CLOSED},\;\mathrm{OPEN}\neq\emptyset, \\
    \infty, & p\notin\mathrm{CLOSED},\;\mathrm{OPEN}=\emptyset.
  \end{cases}
\]

At any fixed stage of the search, this definition is consistent.

\subsubsection{Heuristic Evaluation}
The overall heuristic used is a the maximum of the three consistent heuristics defined above as follows:
\[
  h(s) = \max\{h_{\mathrm{DF}}(s), h_{\mathrm{SC}}(p), h_{\mathrm{EI}}(s)\}.
\]
This overall heuristic remains consistent as it is the maximum of consistent heuristics.

\section{Implementation Details}

\subsection{Data Structures}

The A* and Dijkstra search algorithms are implemented using the following data structures:

\begin{itemize}
  \item \textbf{OPEN:}
        \begin{itemize}
          \item OPEN is implemented as a min-heap.
          \item Insertion and removal have \(O(\log n)\) complexity.
          \item Accessing the minimum element (the top element) has \(O(1)\) complexity.
          \item The C++ Standard Library \texttt{std::priority\_queue} implementation is used.
        \end{itemize}

  \item \textbf{CLOSED:}
        \begin{itemize}
          \item CLOSED is stored as a hash table.
          \item Insertion, deletion, and membership checking have
                \(O(1)_a\) complexity.
          \item The C++ Standard Library \texttt{std::unordered\_set} implementation is used.
        \end{itemize}

  \item \textbf{Parent Pointers:}
        \begin{itemize}
          \item Implemented as a hash table.
          \item If a lower-cost parent to a state is found, it replaces the existing parent.
          \item Lookup, insertion, and update operations have
                \(O(1)_a\) complexity.
          \item The C++ Standard Library \texttt{std::unordered\_map} implementation is used.
        \end{itemize}

  \item \textbf{Costs (\(g\)):}
        \begin{itemize}
          \item Implemented as a hash table.
          \item If a lower cost is found for a state, it replaces the existing
                value.
          \item Lookup, insertion, and update operations have
                \(O(1)_a\) complexity.
          \item The C++ Standard Library \texttt{std::unordered\_map} implementation is used.
        \end{itemize}

  \item \textbf{States:}
        \begin{itemize}
          \item A 3D struct is used to represent the state, containing the x, y, and t coordinates.
          \item A custom hash function is defined for the struct so it can be used efficiently with hash tables.
        \end{itemize}
\end{itemize}

\subsection{Search Algorithms}

The A* and Dijkstra search algorithms use the data structures described above. Duplicate entries are allowed in OPEN to avoid searching for an existing entry and updating its priority whenever a lower-cost path to the same state is found. The priority is \(f\) for A* and \(g\) for Dijkstra. Although OPEN may contain duplicate entries, CLOSED ensures that each state is expanded at most once; subsequent duplicates are discarded. For A*, this behavior requires a consistent heuristic, rather than one that is merely admissible.

An optimal path can be constructed by traversing the parent pointers from any expanded state to a start state.

\subsection{Departure Feasibility and Spatial-Cost Learning}

The learning process consists of two backward Dijkstra searches: one for
departure feasibility and another for spatial cost.

\begin{itemize}
  \item \textbf{Departure feasibility learning:}
        \begin{itemize}
          \item Departure feasibility is learned first because knowing which
                states are infeasible is more useful than improving their spatial-cost
                estimates.

          \item Spatial-cost learning starts only after departure-feasibility
                learning has finished.

          \item Once departure feasibility is fully learned, the planner can
                avoid moves from which the target can no longer be reached. This makes
                the algorithm complete with respect to finding a feasible interception.

          \item A possible source of incompleteness is the robot taking actions
                before departure feasibility has been fully learned.

          \item When the minimum cost in OPEN exceeds the remaining time
                \(T-t\), all states remaining in OPEN, as well as the unexplored
                states, are infeasible. Departure-feasibility learning can then stop,
                since those states will also remain infeasible at later time steps.
        \end{itemize}

  \item \textbf{Spatial-cost learning:}
        \begin{itemize}
          \item Spatial-cost learning begins after departure-feasibility learning
                has been completed.

          \item It improves the cost estimates for reaching the target positions
                while accounting for obstacles and traversal costs.

          \item The spatial-cost search continues incrementally whenever
                planning time remains.
        \end{itemize}
\end{itemize}

\subsection{Planning Algorithm}
\label{sec:real-time-search-framework}

The two real-time planning algorithms use the same planning framework. They differ in their local update procedure \(\mathcal{U}\): RTAA supplies \textsf{RTAA-Update}, while
LSS-LRTA supplies \textsf{LSS-LRTA-Update}.

\begin{algorithm}[H]
  \caption{Real-time heuristic search planning}
  \label{alg:real-time-heuristic-search}
  \KwIn{current state \(s_{\mathrm{current}}\), heuristic \(H\), time limit \(\Delta\),
    expansion bound \(N\), local update procedure \(\mathcal{U}\)}
  \If{\(\FuncSty{IsGoal}(s_{\mathrm{current}})\)}{
    \Return\;
  }
  \(D \gets \FuncSty{CurrentTime}() + \Delta\)\;
  \(D_{\mathrm{learn}} \gets \FuncSty{CurrentTime}()
  + 0.75 \cdot \FuncSty{RemainingTime}(D)\)\;
  \(\FuncSty{RefineHeuristic}(s_{\mathrm{current}},H,D_{\mathrm{learn}})\)\;
  \(R \gets
  \FuncSty{BoundedAStar}(s_{\mathrm{current}},H.\FuncSty{Evaluate},D,N)\)\;
  \(\mathcal{U}(R,H,D)\)\;
  \(s_{\mathrm{next}} \gets
  \FuncSty{SelectNextState}(R,s_{\mathrm{current}})\)\;
  \If{\(\neg\FuncSty{Expired}(D)\)}{
    \(\FuncSty{RefineHeuristic}(s_{\mathrm{current}},H,D)\)\;
  }
  \(\FuncSty{Execute}(s_{\mathrm{next}})\)\;
  \(\FuncSty{RealTimeHeuristicSearch}(
    s_{\mathrm{next}},H,\Delta,N,\mathcal{U})\)\;
\end{algorithm}

\subsubsection{Heuristic Refinement}

Heuristic refinement is independent of the selected real-time search algorithm.
Departure-feasibility learning is completed first; spatial-cost learning then
uses any remaining time.

\begin{algorithm}[H]
  \caption{Incremental heuristic refinement}
  \label{alg:refine-heuristic}
  \KwIn{current state \(s_{\mathrm{current}}\), heuristic \(H\), deadline \(D\)}
  \If{\(H.\FuncSty{FinishedLearning}(s_{\mathrm{current}})
    \lor \FuncSty{Expired}(D)\)}{
    \Return\;
  }
  \If{\(H.\FuncSty{NeedsDepartureLearning}(s_{\mathrm{current}})\)}{
    \(H.\FuncSty{ContinueDepartureLearning}(D)\)\;
    \If{\(\FuncSty{Expired}(D)\)}{
      \Return\;
    }
  }
  \If{\(H.\FuncSty{NeedsSpatialLearning}()\)}{
    \(H.\FuncSty{ContinueSpatialLearning}(D)\)\;
  }
\end{algorithm}

\begin{algorithm}[H]
  \caption{Heuristic evaluation}
  \label{alg:evaluate-heuristic}
  \KwIn{state \(s\), heuristic \(H\)}
  \KwOut{heuristic value \(h(s)\)}
  \If{\(H.\FuncSty{DepartureCost}(s)=\infty\)}{
    \Return{\(\infty\)}\;
  }
  \(h_{\mathrm{spatial}} \gets H.\FuncSty{SpatialCost}(s)\)\;
  \If{\(h_{\mathrm{spatial}}=\infty\)}{
    \Return{\(\infty\)}\;
  }
  \(h_{\mathrm{adaptive}} \gets H.\FuncSty{AdaptiveLowerBound}(s)\)\;
  \Return{\(\max\{h_{\mathrm{spatial}},h_{\mathrm{adaptive}}\}\)}\;
\end{algorithm}

\subsubsection{Local Heuristic Updates}

RTAA performs a direct linear update to all the closed states.

\begin{algorithm}[H]
  \caption{RTAA local heuristic update}
  \label{alg:rtaa-update}
  \KwIn{lookahead result \(R\), heuristic \(H\), deadline \(D\)}
  \(f_{\mathrm{best}} \gets \FuncSty{BestLookaheadValue}(R)\)\;
  \ForEach{\(s \in R.\mathrm{CLOSED}\)}{
  \If{\(\FuncSty{Expired}(D)\)}{
    \Return\;
  }
  \(H.\FuncSty{Update}(s,f_{\mathrm{best}}-R.g(s))\)\;
  }
\end{algorithm}

LSS-LRTA instead propagates heuristic values backward from OPEN to update the expanded states.

\begin{algorithm}[H]
  \caption{LSS-LRTA local heuristic update}
  \label{alg:lss-lrta-update}
  \KwIn{lookahead result \(R\), heuristic \(H\), deadline \(D\)}
  \(V \gets
  \FuncSty{BackwardDijkstra}(R.\mathrm{OPEN},R.\mathrm{CLOSED},
  H.\FuncSty{Evaluate},D)\)\;
  \If{\(\FuncSty{Expired}(D)\)}{
    \Return\;
  }
  \ForEach{\(s \in R.\mathrm{CLOSED}\)}{
  \If{\(\FuncSty{Expired}(D)\)}{
    \Return\;
  }
  \eIf{\(V(s)\) is defined}{
    \(H.\FuncSty{Update}(s,V(s))\)\;
    }{
      \(H.\FuncSty{Update}(s,\infty)\)\;
    }
  }
\end{algorithm}
